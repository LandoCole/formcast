# Plan 3 — controller rulings (exhaustive)

Every decision the controller made on the user's behalf while executing Plans 3A and 3B, in order, copied from the execution ledgers. Each line says what was decided, why, and what it costs if wrong. Implementation facts recorded by implementers (Rulings A–D) are in 2026-10-21-formcast-plan3-rulings.md.

## Plan 3A — browser demo

- Ruling 1: fill (and any) conformance cases that need archived agent templates read copies committed under tests/web/fixtures/templates/ (copied once by the exporter from the extracted archive), so `export_conformance.py --check` and the freshness test never depend on the git-ignored extraction — why: tests must pass on a fresh checkout — cost if wrong: a few hundred KB of duplicated JSON in tests.
- Ruling 2: JS `newFieldId` follows Python `_Run.new_id` exactly (`f{max+1}` over ids matching `_GENERATED_ID`), fixture-tested; the plan's `prefix = "h"` is dropped — why: the spec requires browser templates to replay identically in Python — cost if wrong: none (ids are opaque).
- Ruling 3: showcase.js reads `samples/index.json` beside the page; tests may override the samples base and the detect worker with `?samples=` and `?worker=` query params, honoured only when `location.hostname` is localhost/127.0.0.1 — why: tests need the fixture bundle without shipping test hooks to visitors — cost if wrong: trivial.
- Ruling 4: Task 1 ONNX NMS = IoU 0.1 class-aware (the library's DETECTOR_NMS_IOU, ultralytics default class-aware), not commonforms' fast-path iou=1 (no NMS, 155 boxes on fw9) — why: the spec's 'same NMS commonforms applies' would produce unusable duplicate boxes; matching the library's own NMS is the faithful reading — cost if wrong: browser box counts differ from commonforms CLI output.
- Ruling 5: Task 2 commit trailer says 'Claude Sonnet 5.5' instead of the required Opus 5.5 line — left as is (rewriting history for a trailer isn't worth it); implementer-common.md now says use the exact line — cost if wrong: one commit with a different attribution name.
- Ruling 6: vendored onnxruntime-web keeps the WebGPU+WASM build (26.8 MB wasm, 32.7 MB vendor total) — why: spec wants WebGPU first with WASM fallback; it is loaded only on 'Run live'/dropped flat PDF, never on first paint — cost if wrong: heavier live-detection download; a CPU-only build would save ~13 MB.
- Ruling 7: Task 5 adds `{"type":"module"}` package.json files under demo/web/ and tests/web/ (no deps) so ESM loading doesn't rely on syntax detection, and updates the plan/spec test command to `node --test "tests/web/*.test.js"` with "Node 22+" — why: explicit beats detection; plan text must match reality for later implementers — cost if wrong: two 1-line files.
- Ruling 8: later tasks import pdf.js as vendor/pdfjs/pdf.min.mjs and pdf.worker.min.mjs (Task 4 vendored the minified ESM builds) and must set ort.env.wasm.wasmPaths to the vendor folder.
- Ruling 9: conformance fixtures keep insertion order (not sorted keys) — why: sorting would reorder schema properties and change Python's path order; determinism is what --check needs — cost if wrong: none.
- Ruling 10: path segments from schema.js parsePath use a boxed-String ARRAY_ITEM; every later consumer (ops, values, UI) must use isArrayItem(), never `=== "[]"` — carried into Task 6/7/11/12 dispatches.
- Ruling 11: browser applyOp accepts author 'human' only (agent-only guards not ported) — why: in the browser every edit is a person's; AI edits are applied server-side by Python in the workbench — cost if wrong: none for 3A; 3B never routes agent ops through JS.
- Ruling 12: Task 9 extends contextFromTemplate with optional widgetKinds (from pdf.js widgets) and ports Python's check_widget_kind for set_type/link on widget fields — why: the browser knows widget kinds and Python rejects mismatches with a FormMap context — cost if wrong: small extra code in Task 9.
- Ruling 13: pdf-lib cannot load encrypted PDFs (even owner-password-only, e.g. forms/dev/wadoc_auth.pdf). Browser: such PDFs open, show and detect (pdf.js) but Fill/smart PDF refuse with a plain message that the full library can fill it; sample bundles (Task 13) ship PyMuPDF-saved unencrypted PDFs; Task 12 tests the message — why: no in-browser decryption without new dependencies — cost if wrong: visitors with protected government PDFs can't fill in the demo.
- Ruling 14: unencodable text matches Python (full value in /V, appearance omits undrawable chars, report `unencodable`), resolving the brief's internal contradiction in favour of "match Python" — cost if wrong: none.
- Ruling 15: parity threshold read as pooled over the 3 pages (92/94 = 97.9%; fw9 alone 91.7% from one extra 0.32-confidence box); counts within 5% per page — why: the brief states one threshold for the 3-page set — cost if wrong: one marginal page.
- Ruling 16: browser and sample detections are FFDNetOnnxDetector's own output with no library merge step (single detector, nothing to merge); Task 13 must precompute the same way — cost if wrong: none.
- Ruling 17: model load limit becomes an inactivity limit (120 s without progress) instead of 120 s total, replacing the plan's mandate — why: a total cap kills slow-but-working downloads (102 MB L) and each retry restarts, against the spec's "no stuck spinner"/works-on-slow-links intent — cost if wrong: a stalled-but-trickling download waits longer before failing.
- Ruling 18: Task 10 Minor 3 (px↔pt scaling in pageview.js outside geometry.js) enters the fix round — why: it breaks a Global Constraint in letter ("Only geometry.js converts") — cost if wrong: a tiny geometry helper.
- Ruling 19: Task 12's showcase must guarantee no horizontal page scroll at 375 px even with tags/handles visible (e.g. overflow-x: clip on the page stage, tags constrained inside the page) and test it with a selected small box near the right edge — cost if wrong: minor clipping of a handle edge.
- Ruling 20: Task 12 Minors 1, 2, 4, 5, 6 enter fix round 1 — why: each breaks spec §6/§10.2 ("live detection off by default on phones", "every async step has a visible state and a timeout", no stuck spinner) or the user's stated wince (breaks on mobile / slow); 4: memory decides live detection, pointer+width decide interaction, copy says "this device" — cost if wrong: a slightly larger fix round.
- Ruling 21: Task 13's build_showcase.py owns bundle building; tests/web/make_sample_bundle.py (Task 12) is refactored to call build_showcase helpers so there is one bundle writer, and bundles keep Task 12's manifest.json / agent-scores.json formats — cost if wrong: small refactor.
- Ruling 22: results.json `detection.heldout` (bare-detector baseline from the committed baseline_detection_2026-10-21_heldout.json) stays — why: spec §10.3 explicitly lists held-out detection baselines; quoting committed results tunes nothing; held-out agent files and forms/heldout/ are never read — cost if wrong: one table row group removed later.
- Ruling 23: Task 14 also (a) whitelists agent-scores.json keys in build_showcase.py (run, model_label, form, variant, model, detection, mapping, fill, steps, input_tokens, output_tokens, wall_s, finished — after checking what detect.js reads) and regenerates bundles, and (b) adds group definitions/notes to results.json (fillable/digital = as published; scanned = fake scans; errored sessions excluded; Luna round-2 session count computed from data; §14.3 listed as source of heldout_status) so the page renders explanations from data — cost if wrong: small.
- Ruling 24: Task 14 Minors 4 and 5 enter fix round 1 — 4: Results restructured headline-first (All-sessions table, then caveats and reading, breakdowns and bare-detector tables behind <details>; lead says "on the dev forms"); 5: metric definitions say "a proposed box" so they fit detector tables — why: the page's audience is a skim-reading hiring manager and copy accuracy is an anti-goal item — cost if wrong: one more round of copy edits.
- Ruling 25: Task 16's manual browser smoke is done by the controller in the built-in browser after the implementer's README/check work (subagents can't drive the user's browser pane) — cost if wrong: none.
- Ruling 26: final-review Important 4 (core session controller with an op queue shared by both layouts; widget kinds kept on the doc, not the engine) moves into Plan 3B as a new task before the server engine — why: the race only bites with network latency (server engine), and 3B is where both layouts need it — cost if wrong: the showcase keeps its own (fast, local) apply until 3B lands.
- Ruling 27: final-review Important 3 (real-browser smoke incl. ## Plan 3B — workbench

- Ruling 1: Task 10 (workbench) builds on Task 8's `createSession` (ordered op queue, undo, replaceTemplate for job results) rather than wiring UndoStack/apply itself — why: Ruling 26 of 3A moved session logic into core for both layouts — cost if wrong: none.
- Ruling 2: Task 1 fixtures avoid the real detectors with `build_form_map(pdf, detectors={}, policy=DetectPolicy(digital=(), scanned=()))` or an equivalent no-detector policy (whatever the existing tests use), not a non-existent `detect=False` — cost if wrong: slower tests.
- Ruling 3: accept Task 1's deviations from spec §9.1 — (a) any PDF whose fingerprint differs is capped at 0.94 so "reuse" (≥0.95) means fill would accept it (matches the plan's Review Focus: a changed revision lands in adapt); (b) ink part chance-corrected rather than plain 1−Hamming; (c) label basis uses word pairs — why: each fixes a measured failure on dev forms — cost if wrong: different absolute scores; thresholds live in demo settings. Spec §9.1 to be updated in Task 11 docs.
- Ruling 4: Task 6's matches route computes the uploaded PDF's fingerprints and signature once and passes them to similarity (add an optional precomputed-features parameter or helper in match.py), instead of recomputing per stored template — why: cost grows with the store size — cost if wrong: small API addition.
- Ruling 5: rebind's page-size mismatch message numbers pages from 1 (human-facing message; library internals stay 0-based) — cost if wrong: one-character message change.
- Ruling 6 (carried to Task 7/10): the jobs' cancel callback must not raise SessionCancelled on an event with finished=True (job reports done); the UI says "Stopping after this step…" (cancel is observed between steps); a partial result includes the in-flight step's ops.
- Ruling 7: SqliteRecords(db_path, schemas_dir) and CsvRecords(data folder) signatures accepted (they need the schemas to type columns); KeyError for unknown schema/record/template → Task 5/6 map to 404; pyproject pythonpath gains '.' so tests import demo.server — cost if wrong: none.
- Ruling 8 (carried to Task 5/6): (a) `python -m demo.server` must work without an editable install (formcast isn't importable outside pytest in this venv): __main__ puts the repo's src/ on sys.path when formcast can't be imported, and the README says `pip install -e .`; (b) record-source file errors (cp1252 CSV, empty CSV, csv.Error) become one documented RecordSourceError that routes map to a plain 4xx, and MultiRecords isolates a failing source; (c) TemplateStore.get on an existing but invalid file raises a distinct StoredTemplateError (not ValueError) mapped to a plain error — why: the plan's "never a 500" focus — cost if wrong: small.
- Ruling 9: keep Task 5's additions — Origin≠Host check (403) on state-changing /api requests (stops other web pages in the same browser from spending the user's API credits through the local server), web_root seam, / redirect; StoredTemplateError/RecordSourceError → 422 — cost if wrong: none.
- Ruling 10: FormcastError from the library stays a 4xx with its plain message (the library raises it for deliberate refusals: bad PDF, fingerprint/rebind mismatch, bad template); any other exception is 500 — resolves the reviewer's ⚠️ on spec §11.2 "5xx for library failures" — cost if wrong: status-code nuance only.
- Ruling 11: Task 5 Minors enter fix round 1 because they are security/robustness of a key-holding local server or will multiply in Tasks 6/7: handler timeout (~30 s); X-Frame-Options DENY + CSP frame-ancestors 'none' on all responses; refuse dot-prefixed path parts in static serving; narrow the blanket KeyError→404 / ValueError→400 mapping to the store/records/documents call sites (unexpected ones become 500 and are logged); a process-wide PyMuPDF lock used by renders now (and by fill/form-map builds in Tasks 6/7); quiet handle_error for client resets.
- Ruling 12: Task 6 also takes four small server items from the Task 5 re-review: fix the smuggle tests' inner Content-Length (15→len(body)) so their response-count/document assertions bite; refuse/close on multiple Content-Length headers; treat TimeoutError mid-body as a quiet close (no ERROR traceback); with a wildcard bind, print the 127.0.0.1 URL and say LAN users must bind a specific IP. Task 6/7 take PYMUPDF_LOCK for fills and form-map builds (accepting that a multi-second build serializes renders) — cost if wrong: small.
- Ruling 13: Task 6's API shapes become the contract for Tasks 9/10: {templates}, {template}, PUT {template}→{name, template_id}, DELETE→{deleted}, {schemas:{name:schema}}, {schema, records}, {record}, matches = bare list; errors op_rejected/cannot_rebind (422), bad_author/bad_template (400); /api/seed schema object or stored name; /api/fill record | record_ref | neither.
- Ruling 14: /api/fill and /api/smart-pdf: fingerprint equal → checked fill; template fingerprint null (browser/old) → unchecked fill with fingerprint_note; non-null and different → 409 `fingerprint_mismatch` ("This template was made for a different version of this form. Rebind it to this PDF first.") unless the request sends `check_fingerprint: false` explicitly (then fill with the note). Task 10's UI offers "Rebind to this PDF" on 409 — why: spec §9.2 makes the fingerprint a safety check; the brief's "else False" was too loose — cost if wrong: one extra click for users.
- Ruling 15: Task 6 Minors 2, 3, 5 enter fix round 1: PdfFeatures computes signature/phrases lazily and Doc.has_fingerprint uses only the fingerprints (no full render); a form-map build failure inside /api/apply falls back to template-only validation (no 500 every call; logged); a schema that makes the library recurse (self-referencing $ref) is refused as a 4xx at /api/seed (and fill/apply map RecursionError-type schema failures to a plain 4xx) — why: never-500 focus and library-caller performance — cost if wrong: small.
- Ruling 16: Task 7 Minors 1, 2, 4 enter fix round 1 — a thread that fails to start must not leave a permanent "running" slot; a cancel requested before the first model call ends the job "cancelled" with no paid call (partial = start template for adapt/revise, null for build); Job.request_cancel() instead of reaching into _cancel — why: permanent 429 and spending the user's credits after they pressed cancel — cost if wrong: small.
- Ruling 17: Task 8 Minor 1 (malformed engine result rejects instead of resolving {error}) enters fix round 1 — why: the session's "always resolves" contract is what layouts rely on — cost if wrong: none.
- Ruling 18: server pages keep unrotated width/height plus their real rotation (server summary gains `rotations`), overriding the plan's 'rotation: 0 with rendered size' — why: template rects are in unrotated space and PageView places boxes over a rotated image via geometry.js exactly as it does for pdf.js renders; the plan's version would misplace every box on rotated PDFs — cost if wrong: none (additive server field).
- Ruling 19 (carried to Task 10): the workbench keys AI/matches controls on engine.capabilities (server engine exposes build/revise/matches methods regardless); uses no browser-only doc fields (bytes, widgetKinds, textLines, cropBox) and server error codes (bad_pdf) rather than DocError codes; adds one end-to-end Playwright check that a /Rotate 90 PDF's rendered image and a box over a known rect line up; shows fingerprint_note for smart PDFs if cheap (or documents its absence).
- Ruling 20: accept Task 10's calls — Reuse loads the stored template as is (fingerprint differences surface as the 409 rebind prompt at fill time); Adapt shows the seed first so one Undo returns to it; the job panel is modal during a job; record lists deduped by id across CSV+SQLite — cost if wrong: small UX changes.
- Ruling 21: Task 10 Minors 1, 2, 3, 5 enter fix round 1 — Adapt checks page count only (start_from handles size changes); Cancel re-enabled on failure plus a way out of the panel; ignore non-primary buttons for the held-pointer flag; focus moved into and trapped in the modal job panel (no edits behind it) — why: wrong refusals, stuck states and silent overwrites — cost if wrong: small.
- Ruling 22: final fix wave (3B) takes Important 1, 2; must-fix minors (README make_server swap mechanism, records.sqlite in data-dir layout, port-range check); Minor 3 (server-side page-count check for adapt/revise), 4 (route on the raw path so record ids with "/" work), 6 (fill drawer "Sample record" via placeholderRecord for pasted schemas), 7 (export pdf_features/PdfFeatures and document similarity(..., features=)); plus the two smoke observations (path tags overlapping on dense rows in both layouts → constrain tags to the box width with full text on hover/focus/selection; AI-off note wraps) and a portfolio re-sync — why: day-one developer issues and visible polish — cost if wrong: one more review pass.
