# PDF extraction: rulings made while building plans 1-3

Each line is a decision taken during subagent-driven implementation, where the spec
(docs/superpowers/specs/2026-10-28-pdf-extraction-design.md) or a plan was silent, wrong or in
conflict. The form is `Ruling: what was decided — why — what it costs if wrong`. Copied from the
build ledgers, which are scratch and are deleted after the build.

## Plan 1: the extraction core (2026-10-28-pdf-extraction-core.md)

- Ruling R1: Task 9's CLI test expects values.csv with 20 data rows (the 2 other forms go to set_aside.csv), not 22 — spec and Task 8 say failed documents are never value rows — cost if wrong: one assertion.
- Ruling R2: extract() rule 1 counts a fingerprint match when PdfFeatures.matches_fingerprint(template.form.fingerprint) is true (full or blind), since form_info_for stores the blank form's full fingerprint — cost if wrong: fillable copies would show matched="layout" instead of "fingerprint".
- Ruling R3: no top-level `formcast.extract` function export (it would collide with the subpackage `formcast.extract`); Task 9 lazily exports ExtractionTemplate, scan, run_batch; extract() is `formcast.extract.extract` — cost if wrong: one rename.
- Ruling R4: Task 3 tests call after_phrase(["account"], 0, "digits") (list form) — cost if wrong: none.
- Ruling R5: layout static-line text is normalized as casefold, non-letters/digits to spaces, whitespace collapsed ("Taxpayer ID:" -> "taxpayer id"), a helper in layout.py separate from label_key — cost if wrong: one helper.
- Ruling R6: Tasks 3 and 5 may add keyword options to tests/extract/corpus.py make_form for the variants their tests need (a duplicated label, extra checked boxes), keeping defaults unchanged — cost if wrong: corpus grows a few options.
- Ruling R7: hand_template's form info comes from the blank FILLABLE form — cost if wrong: flattened copies are unaffected; only fingerprint routing would change.
- Ruling R8: hand_template schema paths fixed as investor.{legal_name,tax_id,dob,type,country}, address.{street,city_state_zip}, owners[i].{name,percent(string)}, wire.{bank,account}; investor.type has a widget choice and a drawn-box choice strategy — the plan named only some paths — cost if wrong: renaming paths in tests.
- Task 2: minor (deferred): investor.tax_id required only inside investor, so {} validates — see Ruling R9
- Ruling R9: Task 5 makes the hand_template schema also require "investor" at the top level, so a document with no investor answers reports tax_id missing — spec says required means every document must have it — cost if wrong: one schema line.
- Ruling R10: text_right_of stops before a run of words on the row that ends in ":" (the next label); no first-word gap limit beyond max_width (labels often sit far from answers) — brief's stop rule cannot see multi-word labels; spec forbids silent wrong values — cost if wrong: an answer containing "word:" text is cut short (shows as missing/failed, not wrong).
- Ruling R11: radio groups: widget_value(name) returns the selected kid's on-state string (None when off) for a group whose kids have different on-states; ChoiceMark gains `state: str | None = None` (only with widget) and DocText gains widget_on(name, state=None) -> bool | None, so a choice option can address one kid — brief's API was by name only — cost if wrong: small model/API addition.
- Ruling R12: `digits` (and `line`) stops end at the end of the phrase's own text line; comma/sentence may cross lines — cost if wrong: an account number wrapped onto the next line reads short (fails/missing rather than wrong).
- Ruling R10b (replaces the capitalisation heuristic of round 1): when a later word on the row ends in ":", the answer is the words before the widest gap > 1 em that precedes that colon word (the gap that separates answer from the next label); if no gap > 1 em lies between the answer's first word and that colon word, return None — no guessing from letter case — cost if wrong: single-space rows like "Name: Dana Keller Date of birth:" read as missing (review sees them), never wrong.
- Ruling R13: leave commit 488de58's "Co-Authored-By: Claude Sonnet 5.5" trailer (that subagent's own attribution; accurate for its author) rather than rewrite history — cost if wrong: one trailer differs from the plan's line.
- Ruling R14: accept that filled corpus fillable copies route by "layout" (their wire paragraph is page text, so the blind fingerprint differs); fingerprint path stays tested on the blank — cost if wrong: none for correctness; Task 7 tests expect "layout".
- Ruling R15: an unsure field carries a reason in `reasons` ("label found in N places", "layout not matched") so review can see why — spec item 3 asks readers to report places; no model change — cost if wrong: wording.
- Ruling R16: drop side="inside" from AnchorRead's Literal (nothing implements it; silently reading as "right" is a misread) — cost if wrong: re-add when plan 2 needs it.
- Ruling R17: when a later strategy replaces a first candidate that failed its check and the values differ, the field is `unsure` (reason names the first read), not `found` — brief says later wins; spec forbids silent wrong — cost if wrong: more review items on fillable forms with stale appearances.
- Ruling R18: extract() reports non-PDF exceptions (code/template bugs) as "internal error: <Type>: <msg>" rather than "cannot read PDF", still without raising — cost if wrong: wording of the error.
- Ruling R19: a document with no text layer joins only a group whose first member also has no text (and vice versa); cross-layout calibration uses tracked same-size 2-page Letter forms from forms/dev (e.g. columbus_medhist, f8949, csudh_health) and is pinned in the test instead of the W-9; a test proves a blank 2-page Letter PDF stays apart — spec forbids widening across layouts — cost if wrong: image-only scans of the main form form their own group (visible, not merged).
- Ruling R20: ScanGroup gains `closeness: float | None` — the signature similarity of the group's first member to the main group's first member (None for the main group) — the spec says the group's closeness to the main one tells an edition from a stranger; the brief omitted it — cost if wrong: one extra field.
- Ruling R21: keep the spec's routing order (blind fingerprint, then layout) even though fingerprinting costs ~60% per document and rarely hits on filled forms whose answers include page text; flag to the user as a throughput option (layout first would roughly double speed) — cost if wrong: ~2x slower batches until changed.
- Ruling R22: when the pool breaks, re-read each in-flight document alone in a fresh one-worker pool; one that breaks it is recorded "cannot read PDF: the reader crashed" and the run goes on with a new pool; per-document hang timeout is deferred (killing one hung worker needs process control the executor lacks) — Review Focus requires the run to continue — cost if wrong: a hanging PDF still stalls a run.
- Ruling R23: no similarity tie-breaker between templates with equal layout scores (brief omitted it; ties go to the first template) — cost if wrong: rare mis-route between near-identical templates; revisit with plan 2's multiple templates.
- Ruling R24: the spec's per-field summary (found/missing/failed/reviewed per field) belongs to plan 3's review view; RunSummary keeps document counts — cost if wrong: Task 8/9 add a small helper later.
- Ruling R25: pyarrow is not installed in the shared .venv; do not install it mid-run (it changes the user's environment) — the Parquet round-trip test uses importorskip and will skip; the missing-extra error is tested; flag to the user to install formcast[parquet] and run tests/extract/test_export.py — cost if wrong: the Parquet writer ships unexercised until then.
- Ruling R26: export raises FormcastError naming the column when a template column equals a document column, or when templates map one column to different paths or types — template author renames the path — cost if wrong: a template with a field named "file" must rename it before export.
- Ruling R27: CSV values stay unaltered (no formula-escaping) since exports feed data pipelines and "-5"/"+1 555" are real values; documented in the module; a guard option can come with the CLI or plan 3 — cost if wrong: a CSV opened in Excel could evaluate a crafted cell.
- Ruling R28: export takes --template T.json (run.json stores only ids and names) instead of the brief's template-less form; follow-up: run_batch copies templates into OUT so export can find them — cost if wrong: one extra CLI argument until then.
- Ruling R29: `run` prints progress and its summary on stderr, nothing on stdout — cost if wrong: scripts reading stdout get nothing.
- Ruling F1: on a matched layout anchor reads never take static-line words; cross-field duplicate raw or overlap with another path's box -> unsure; text_below starts only directly under the label — cost if wrong: some legit answers that equal another field's read come out unsure.
- Ruling F2: a box read is trusted only when the nearest static line above it and any on its row are found at the page offset; else skipped with doubt "layout differs near this box" — cost if wrong: more anchor fallbacks/missing on slightly reflowed copies.
- Ruling F3: integer/number coercion in read.py keeps raw (failed_check) for non-whole ints and non-3-digit comma groups — cost if wrong: "1,5" style decimals fail rather than read.
- Ruling F4: run.json stores template sha256; resume and CLI export refuse a mismatch; RunSummary gains internal_errors (not counted unreadable); no retry option — cost if wrong: editing a template forces a new out_dir.
- Ruling F5: run_batch timeout=120 s per document (CLI --timeout); a hung document terminates the pool, is re-read alone, and is recorded "cannot read PDF: the reader hung"; workers=1 has no timeout — cost if wrong: a legitimately slow 120 s+ document is set aside.
- Ruling F6: Parquet verified once more with cached pyarrow via PYTHONPATH; nothing installed; user runs it with formcast[parquet] — cost if wrong: an untested pyarrow floor (>=15).
- Residual (load-bearing, surfaced to user — no second fix wave per process): C1 joined-printed-line regression.
- Ruling F7: a word is printed when it is one of the words of the document line at a stop_at rect (fallback for a rect that is no line: words whose middle lies in it), not when its middle lies inside a printed line's bbox; only the printed words carrying on the label (each within LABEL_GAP_EM of the one before, up to the first ending ":") are passed over; text_below stops at a line holding a printed word — cost if wrong: a printed word with no gap after a colon-less label ("Phone (home)") is passed over and the answer read after it, as intended; a printed word glued to an answer on one PDF line is not detected (that line does not match the layout anyway).

## Plan 2: AI template building (2026-10-29-pdf-extraction-setup.md)

- Ruling R1: T6's `result.warnings == []` becomes "no warning says a path has no way to be read" (dropped alternative wordings such as hand_template's "TIN" are fine and expected) — CorpusModel proposes from hand_template's readers, whose alternative labels are not all printed on the corpus form, so resolve rightly warns about them — cost if wrong: a test that tolerates harmless warnings.
- Ruling R2: `proof.ready == proof.total` (plan 2 T6, add_line test; plan 3 T4/T7) becomes: every field present on at least one sample is ready and no sample outcome is `disagree`; a field missing on every sample (an owner row no sample fills) stays not ready — the spec says ready means agreeing where present, and a field present nowhere cannot be proved — cost if wrong: weaker test assertions; plan 3's UI shows such fields as ◐ / × rather than ●.
- Ruling R3: T7's AI-pass tests write their own batch folder: corpus copies plus at least two copies with a blank tax ID (dataclasses.replace(client, tax_id="")), so the failing set is never empty — the corpus folder's documents may all have tax IDs — cost if wrong: none.
- Ruling R4: a raw match counts as agree only when the reader's own clean steps and type coercion, run on the opinion, give a value same_value() to the read value; a value match stays agree as before — the plan's raw-agree rule let a transform that changes the answer pass the proof, against the spec's "never a silent wrong value" — cost if wrong: a reading the model gives in printed form that the reader's clean cannot reproduce (rare) shows disagree for review.
- Ruling R4b: amends R4 (the implementer showed R4 alone still agrees on CA->US: cleaning the opinion with the same wrong map gives the read value): a raw-text match counts only when the schema refuses the model's answer at that path (the printed-form case, "04/19/2011" for a date) and the opinion cleaned the reader's way equals the read value; an answer the schema accepts must equal the read value itself; the same for failed_check — cost if wrong: a model answer that is valid but in another valid form than the reader's value shows disagree (review).
- Ruling R5: sample_view adds, for each page that is not fillable, a `PAGE n TEXT:` section of the page's own text lines (DocText.lines: `[x0,y0,x1,y1] text`), and the cut keeps the header and FORM FIELD VALUES whole (they come first after the header; page summaries and page text share what is left, page by page); values written with json.dumps — the plan's view (summarize_page alone) would leave the model unable to read a flattened sample's answers without images, so its second opinion and reader proposals would fail on half the samples — cost if wrong: a longer view per sample (bounded by SAMPLE_CHARS).
- Ruling R6: a ChoiceRead with one option on a boolean path uses lone mode only when the option key coerces to a boolean (true/yes or false/no, case-insensitive, via the same _bool rule as mapping): marked -> that boolean, unmarked -> its opposite; any other key keeps plan 1's behaviour (marked -> key, unmarked -> nothing). An unmarked lone read counts as empty for the repeated-item absent rule (an item whose fields are all empty or unmarked lone boxes is absent; its boolean is absent, not False) — the plan's "True when marked" did not foresee keys meaning no, and the spec makes an empty row absent — cost if wrong: none known.
- Ruling R7: "email" added to the prompt guard's GENERIC_NAMES is accepted — the fields prompt must name the `email` format, and "email" is a plain English word like the list's others — cost if wrong: the guard no longer catches a corpus property literally named email.
- Ruling R8: Task 6's build_setup/add_line warn "<path>: the model proposed no way to read it" for every asked path propose_readers returned nothing for (resolve already warns about paths it got but could not use) — a silently reader-less field would otherwise look the same as a field the model forgot — cost if wrong: none.
- Ruling R9: ask.py's asked-paths listing keeps `_schema_lines` and appends each leaf's title, `format`, `pattern` and whether it is required (local to ask.py; _schema_lines unchanged) — the plan mandated _schema_lines without seeing it drops format, yet the prompts rely on dates being known — cost if wrong: longer prompts.
- Ruling R10: decide() turns an accept of a field whose value came from an AI answer (strategy "ai") into a "value" decision carrying that value (so it stands on its own), and _decided refuses to show an accept as found when the field it applies to has no value (it stays as read) — keeps "the AI's values are always reviewed" true whatever ai.jsonl holds later — cost if wrong: none.
- Ruling F1: learned wordings become FieldProof.suggested (guards: not a static layout line, not another path's raw on that sample); build_setup/add_line no longer apply learn_maps; learn_maps applies suggestions when the person accepts — the spec says the person checks the map — cost if wrong: fields with wording variation the model's own map missed are not ready until the person accepts the suggestion.
- Ruling F2: a boolean choice that lost an option emits no ChoiceRead (warning); non-boolean keeps survivors; widget_places ignores state for plain check boxes — cost if wrong: such a field needs a person to draw the box.
- Ruling F3: template_sha256 excludes setup and samples — cost if wrong: editing a template's samples does not mark a run's results stale (they never affect a read).
- Ruling F4: SessionCancelled re-raised unchanged in samples.py — cost if wrong: none.
- Ruling F5: SetBox/SetOptionBox take optional sample index; apply_edit(..., pdfs=) moves a sample-frame rect into the layout's place by the sample page's offset (shared with resolve) — cost if wrong: one more argument on edits.
- Ruling F6 (minors folded): blind fingerprint in a built template's form; MAX_SAMPLES in _LAZY; decide applies AI answers without decided paths; SetupInfo keeps pages/ocr/vision; samples.py in MODEL_FACING; path-only proposal warning wording.
- Residual: parked — a model proposing only the "false" option of a Yes/No pair makes a lone box, so an unanswered copy reads found True — Ruling: parked and surfaced to the user (no second fix wave); a genuine "check if NOT" box looks the same to resolve, and the READERS prompt asks for both options; the proof catches it only when a sample is unanswered — cost if wrong: such a form reads unanswered copies as yes.
- Residual: deferred minor — the printed-text guard for suggestions matches whole static lines only (a box over part of the title can still suggest it); not silent, a person must accept.

## Plan 3: the workbench (2026-10-29-pdf-extraction-workbench.md)
