# Plan 3 rulings: facts and decisions made during implementation

- Ruling A (Task 1): FFDNet ONNX graph facts, read with onnxruntime 1.31 from `jbarrow/FFDNet-S-cpu` / `FFDNet-L-cpu` (Ultralytics 8.3.204 exports, `nms: False`, opset default, fixed shape, batch 1) and checked against commonforms 0.2's `fast=True` path.
  - **Input**: one tensor named `images`, `[1, 3, 1216, 1216]`, float32, RGB, channels first, values `/ 255` (0..1), no mean/std.
  - **Output**: one tensor `output0`, `[1, 7, 30324]` float32 (30324 = 152² + 76² + 38² anchors for strides 8/16/32). Rows 0-3 are box centre x, centre y, width, height in input pixels (0..1216, not normalized); rows 4-6 are the class scores for 0 textbox, 1 choice_button, 2 signature, already sigmoided (0..1). There is no objectness row.
  - **No NMS in the graph** (ops are Conv/Resize/Concat/Sigmoid/Slice etc., no NonMaxSuppression), so the caller does everything after the tensor: take each anchor's best class and score, drop scores under the confidence, convert xywh to xyxy, per-class NMS, cap at 300 boxes, undo the letterbox.
  - **Letterbox** (ultralytics `LetterBox` with `auto=False` because the model is not `.pt`): scale = min(1216/w, 1216/h) (upscaling allowed), resized size = round(w*scale) x round(h*scale), image centred, padding colour (114, 114, 114), left = round((1216 - new_w)/2 - 0.1), top = round((1216 - new_h)/2 - 0.1) (the right/bottom side takes the rest). Resize is bilinear (OpenCV `INTER_LINEAR` in ultralytics; the Python port uses PIL bilinear, which antialiases when shrinking, so a page rendered at 144 dpi (1224 x 1584 for Letter) differs from ultralytics by resampling only). Box back to the image: `(v - pad) / scale / image_size`, then clamp to 0..1.
  - **NMS IoU to apply: 0.1, class-aware**, the library's `DETECTOR_NMS_IOU` and the value ultralytics applies on the `.pt` path (`agnostic=False`). commonforms' own `fast=True` path calls `predict(iou=1)`, which suppresses only identical boxes: on `forms/dev/fw9.pdf` page 0 that leaves 155 (S) and 170 (L) boxes where the `.pt` path with TTA gives 23, so it is not usable as a reference. With IoU 0.1 the Python decode gives 23 boxes for both S and L on that page; with IoU 1.0 it reproduces ultralytics' ONNX output (S 156 against 155, L 163 against 170, 153 and 162 of them paired at IoU > 0.9; the differences are borderline-score anchors under resampling), which validates letterbox, layout and class order.
  - **Confidence** 0.3 (`FFDNetOnnxDetector` default), as the library's detectors.
  - **Not exported**: `augment=True` (test-time augmentation) does not exist for ONNX, so single pass is all the browser gets; Task 1's measurement compares it with the augmented `.pt` L.
- Ruling B (Task 2): reproduction check of the `defer-placement` templates. The 24 saved templates were copied from the other worktree's `eval/results/templates/2026-10-21_defer-placement/` (3.0 MB, copied not moved) and `agent_eval.py --rescore` was run on the committed results json (no model calls; it needed only the templates, no step logs or form-map logs). Every row's detection and mapping fields, the baseline fields and the detection/mapping totals came out identical to the committed file; the only differences are the new `fill` fields and the meta `rescored` and `notes` text. **Reproduced exactly; archived** in `eval/results/templates.tar.gz` (263 entries, 231 files), so Task 13 may use the `defer-placement` templates for the samples' agent templates and the headline row. `fill_acc` for this run: 0.579 overall (9,324 of 16,098 units), fillable 0.93 (7 sessions), digital 0.58 (5), scanned 0.45 (12); as published 0.71, fake scan 0.45. The archive keeps its existing layout (entries under `eval/results/templates/`, extract from the repo root); it was rebuilt with Python `tarfile` (uid/gid 0, mtime 0, sorted) because the brief's `-C eval/results templates` form would have changed the entry prefix and macOS tar has no `--mtime`.
