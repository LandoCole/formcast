# formcast Plan 3A — Browser demo (web core, browser engine, showcase page, portfolio) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A static, no-server formcast demo for landonthornton.com: the CommonForms detector runs in the visitor's browser, the visitor links boxes to a JSON Schema by hand, fills the form and downloads the PDF, with real benchmark numbers below; built from shared vanilla-JS parts that Plan 3B's local workbench reuses.

**Architecture:** Pure-logic ES modules in `demo/web/core/` (geometry, transforms, schema, ops, values, undo) are ports of the Python library held to it by fixtures that a Python script generates by running the real code. UI parts (page view, schema list, inspector, history, report) mount into any layout. A browser engine (`demo/web/engines/browser/`) opens PDFs with pdf.js, detects with FFDNet ONNX in a Web Worker via onnxruntime-web, and fills with pdf-lib. The showcase page (`demo/web/showcase/`, layout C) wires them together; a sync script copies it into the portfolio site.

**Tech Stack:** Python 3.12 (formcast, PyMuPDF 2.0, onnxruntime 1.31), vanilla ES modules, pdf.js, pdf-lib, onnxruntime-web (all vendored, pinned), Node 24 `node --test`, Python Playwright + Chromium.

**Spec:** `docs/superpowers/specs/2026-10-21-formcast-review-apps-design.md` (read it first; section numbers below refer to it). Main spec: `docs/superpowers/specs/2026-10-20-form-projection-design.md`. Fill spec: `docs/superpowers/specs/2026-10-21-formcast-fill-design.md`.

## Global Constraints

- Vanilla HTML, CSS and ES modules. No frameworks, no bundler, no build step for web code. No npm dependencies (tests use `node --test` only).
- Third-party browser libraries vendored in `demo/web/vendor/` at exact pinned versions released at least two weeks before 2026-10-21, each with its licence file; listed in `demo/web/vendor/README.md`. Nothing loads from a CDN at runtime except the model weights.
- Model weights load from `https://huggingface.co/jbarrow/FFDNet-S-cpu/resolve/main/FFDNet-S.onnx` (38,370,092 bytes) and `https://huggingface.co/jbarrow/FFDNet-L-cpu/resolve/main/FFDNet-L.onnx` (101,944,542 bytes). Never re-host, re-export or quantize them.
- Coordinates everywhere are PDF points, origin top-left, unrotated crop-box space (as in the library). Only `demo/web/core/geometry.js` converts to screen pixels or PDF user space.
- Python is the reference. Every JS port of library logic is checked against fixtures generated by running Python (`demo/tools/export_conformance.py`).
- Portfolio look: Flexoki neutrals only (light `--paper #FFFCF0`, `--ink #100F0F`, `--graphite #6F6E69`, `--panel #E6E4D9`; dark `--paper #100F0F`, `--ink #CECDC3`, `--graphite #878580`, `--panel #282726`), 24px dot grid, label column 168px / gap 48px / text column 672px, EB Garamond (public repo; Michelangelus swapped in by the portfolio sync) + IBM Plex Mono, light and dark themes, no accent colours. Box states by line style only: linked solid ink, not linked dashed graphite, selected 2px ink with handles.
- Copy: plain, calm, no hype; follow the portfolio's `CLAUDE.md` and `tools/check_site.py` copy rules.
- No form-specific code or sample-specific branches. No real-model (paid) API calls. Never read `.env` or print keys. Never read or use `forms/heldout/` or held-out results for anything except quoting committed held-out status lines on the page.
- Existing tests (1,035 passing, 4 deselected) keep passing: `.venv/bin/python -m pytest -q`.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Don't push. Don't merge to `main` (the controller does that).
- Work happens on branch `formcast-plan3` in worktree `.claude/worktrees/plan3` (created by the controller from `main`). Portfolio work (Task 15) happens in a separate worktree of the portfolio repo (§6).
- JS style: ES2022 modules, named exports, JSDoc on exported functions, 2-space indent, no semicolon-free style mixing (use semicolons). Python style: match `src/formcast` (type hints, docstrings, `from __future__ import annotations`).

## Review Focus

- **Rotated pages and crop-box offsets** (common in scanned-then-saved and government PDFs): boxes must sit on the right place on screen and in the filled PDF. Owned by Task 4 (geometry tests with rotation 0/90/180/270 and a crop-box offset) and Task 8 (fill a rotated fixture and read the rects back with PyMuPDF).
- **Non-Latin text in records** ("Sí", "José", "Zürich", "北京"; the Plan 2 crash was a checkbox option named "Sí"): the browser fill must never throw; encodable Latin-1 text is written, anything else is reported `unencodable`. Owned by Task 8.
- **Bad PDFs dropped by a visitor** (encrypted, corrupt, not a PDF, 0 pages, 200 pages): a plain message in the Detect step, previous state kept, no stuck spinner. Owned by Task 9 (`openPdf` errors) and Task 12 (UI message test).
- **Pasted schemas that break or change** (invalid JSON, `$ref` cycle, unsupported keywords, a new schema that drops a path already linked): error under the text box with the old schema kept; boxes whose path no longer exists flagged in the inspector and the schema list, never silently unlinked. Owned by Task 5 (flatten errors) and Task 12 (UI test).
- **A template loaded for the wrong PDF** (page count or sizes differ): refused with a message naming the mismatch. Owned by Task 12 (`store.js` load test).
