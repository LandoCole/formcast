- Task 1: Style rejects NaN/inf/<=0 for font_size and min_font_size, and an explicitly set min_font_size above a numeric font_size (Ruling D). An unset min is lowered to a smaller numeric font_size (Style(font_size=5) gives min 5); set_style with only font_size takes min(existing min, new size). All 207 archived eval templates (eval/results/templates.tar.gz) still load under these rules. revise() and build_template() both return SessionResult (use .template). The agent Session builds OpContext without widget_kinds (agent code is frozen), so the kind check applies only to callers that pass widget_kinds (OpContext.from_template(t, form_map) does).
- Task 2: resolve() record-level rules. unmapped_data flags leaf schema paths (scalar/enum/date/scalar-array, plus a list-of-objects path as one table) that have a non-missing value and aren't covered by a mapped field; a mapped table covers only its column keys (an uncovered column with data is flagged as `table[].col`), an unmapped table is flagged once at the table path. unknown_keys is one info warning listing schema-style paths of undeclared keys, skipped for objects where validation already reports "Additional properties". A bad table row's `invalid` goes in TableResolved.warnings (path = table path, row index in the message), its cells still exist with text None. Field warnings carry the field's page/rect; `missing` carries `path` only when the field has a single source path. Source.join is a separator applied only when the post-transform result is a list (no list_joined note then).
- Task 3: fit_text shrinks only on width (single line), on height+max_lines (multi-line), or on cell width+height (comb); a numeric font_size is never height-checked for single line. Multi-line overflow reports `lines` as the wrapped count at min_font_size. Comb cell width = rect width / n with no PAD; comb uses the widest glyph of the (cut) text. max_len and comb combine as min(). `\n` is a hard paragraph break when wrapping. pymupdf.get_text_length(text, fontname="helv", fontsize=...) works in PyMuPDF 2.0.
- Task 4: binding. (1) A signature-kind widget (named or adopted, field type signature) keeps its `how` and gets a `not_writable` warning; the writer skips it. (2) `choice_mark` targets never use or adopt foreign widgets and any `existing_widget` on one is ignored (no warning); see Ruling H. (3) Adoption excludes every widget whose name any non-choice_mark target names (not only the one picked), so unrelated cells never grab a sibling kid of a named radio/checkbox group; this includes widgets behind a `type_mismatch`. (4) Adoption order is page, rect top, rect left, key; ties between candidate widgets go to the lower page.widgets() index. (5) New names are assigned in input order of `targets`, suffixes `_2`, `_3`, … against all existing widget names (any page) and earlier new names. (6) `widget_name_for` turns the first `[n].` into `_r<n>_`; a plain field id containing that pattern would be read as a cell key. (7) Binding warnings carry field=target.field_id, page, rect=target.rect.
- Ruling G (Task 4 fix): bind() does not detect two targets resolving to the same ExistingWidget (both get how="named" with that widget); Task 6 groups written targets by widget instance and compares values.
- Ruling H (Task 4 fix): a choice_mark may adopt (how="adopted", info `adopted`) an unclaimed existing checkbox widget named widget_name_for(key) or that name plus `_N`, with IoU >= 0.5 against its rect, so refilling a formcast-filled PDF doesn't stack a second circle mark; it adopts nothing else.
- Ruling I (Task 4 fix): generated widget names never contain "." "[" "]": widget_name_for turns each run of them (with adjacent underscores) into one "_" and strips trailing "_" (`t[0].sched.time` -> `t_r0_sched_time`); collisions are still resolved by `_N` suffixes.
- Task 5 spike (a) (PyMuPDF 2.0 / MuPDF 1.28.5): a created text widget keeps value, text_fontsize, Helv, the multiline and comb flags and text_maxlen through tobytes() + reopen. PyMuPDF 2.0 always splits a created widget into a parent field (/T /FT /Ff /DA /MaxLen /Q /V) plus a widget kid. There is no Widget quadding attribute, and MuPDF's appearance generator reads /Q only from the widget annotation itself (not inherited from /Parent), so the writer sets /Q on the created kid (and its parent field); for named/adopted widgets it copies an inherited non-zero /Q onto the widget so the regenerated appearance keeps the form's alignment.
- Task 5 spike (a2): Widget.update() writes /DA, /MaxLen, /Ff and the name only on a field-widget (no /Parent); on a kid (every IRS widget, every widget PyMuPDF 2.0 creates) a new text_fontsize is silently ignored. The writer therefore puts the fitted /DA ("<color> /<font> <size> Tf") on the widget annotation itself before update(). update() with an empty text value does not clear /V; clearing uses mupdf.pdf_set_field_value(..., "", 1) then update().
- Task 5 spike (b): on menomonie group_1, field_value = kid.on_state() + update() sets that kid on and every sibling /AS Off (parent /V = that on-state); field_value = False turns a kid off. field_value = "Off" turns a radio kid ON (PyMuPDF tests `if not value`), so the writer uses on_state()/False for every existing button, never the string "Off".
- Task 5 spike (c): MuPDF's regenerated text appearance honours only Helv, Cour and TiRo (ZaDb kept as PyMuPDF's 4th valid name); any other /DA font (HeBo on i9, HelveticaLTStd-Bold on f8949/fw4/fw9, Arial on ds11) is drawn in Helvetica, and Widget.update() rewrites a field-widget's /DA font to Helv. Rule: a named/adopted widget whose /DA font is not Helv/Cour/TiRo/ZaDb gets /DA Helv plus an info `font_substituted`; a kept font stays and only the size changes. `write.text_font_for(page, binding)` returns the font the appearance will use, so fitting can measure with it (pymupdf.get_text_length accepts Helv/Cour/TiRo/ZaDb).
- Task 5 spike (d): a custom /AP << /N << /Yes ellipse-form /Off empty-form >> >> written on a checkbox after its last update() survives tobytes() + reopen + re-save unchanged; PyMuPDF/MuPDF does not regenerate it on open or save. Any later update() replaces it with the ZapfDingbats check, so write_choice_mark always rewrites the custom AP after update() (also on an adopted refill, Ruling H). No annotation fallback is needed.
- Task 5 spike (e): checkbox circle style is not settable: MuPDF's checkbox appearance ignores /MK /CA and always draws the ZapfDingbats check. Created radio_option checkboxes use the default check; write_choice's style_circle is accepted and has no effect.
- Task 5 spike (f): PyMuPDF can build a proper radio group for test fixtures by adding RADIOBUTTON widgets with the same name and field_value = the desired on-state (each kid's on-state comes from its field_value, all kids share one parent); the fixture then sets parent /V and kid /AS to /Off.
- Task 5: created widgets are placed with widget.rect = the template rect (unrotated crop-box space); PyMuPDF converts for /Rotate and an offset cropbox, and the rect reads back identically (rotate 0/90/270, cropbox (36,36,576,756)).
- Task 5: the writers take the target rect as a keyword `rect=` (Binding carries none); it is required for how="created". write_text writes `fit.text` when a Fit is given (already cut for comb/MaxLen), else `text`; font size is fit.font_size, else a numeric style.font_size, else the widget's current size. Writer warnings carry page and rect (the widget's rect read back), not field; Task 6 sets field. The writers raise ValueError for how="none" or a signature-kind widget (Task 6 skips those).
- Ruling J (Task 5 fix): kids of a field that fill writes (same terminal field, any page) share its value, so after writing or clearing one kid the writer regenerates every sibling kid's appearance with update(), each keeping its own /DA (checkbox siblings get /AS = their on-state if it equals the new value, else /Off; PyMuPDF already does radio kids). "Untouched" in the constraints means widgets of fields fill does not write.
- Ruling K (Task 5 fix): style.align and style.multiline change an existing (named/adopted) widget only when explicitly set on the field's Style (`"align" in style.model_fields_set`, likewise multiline); the new /Q goes on the terminal field, the widget and its sibling kids, the multiline bit on the field's /Ff. Defaults keep the widget's own /Q and flags.
- Ruling L (Task 5 fix): a combo/list value equal to an option's export value is written as is; one equal only to an option's display text is written as that option's export value (no warning); a value matching neither is written anyway with `not_an_option`. Options are parsed by the shared `pagemap.extract.choice_pairs`.
- Ruling M (Task 6): the fingerprint's text layer includes what widget appearances draw (PyMuPDF get_text runs fz_run_page, annotations included), so a filled PDF's plain fingerprint differs from its blank's and a refill would fail the check. `fingerprint_document(doc, ignore_field_values=True)` fingerprints a copy with every text/combo/list/checkbox/radio widget hidden (flag bit 2; signature and push-button captions still count, as they do in the blank's own fingerprint). fill accepts a PDF when either fingerprint equals the template's. On all 17 corpus blanks the field-blind fingerprint equals the plain one, so stored fingerprints are unchanged. Limitation: a blank whose text widgets carry default values can't be refilled with check_fingerprint=True.
- Task 6: fill saves with `tobytes(garbage=1, deflate=True)`, not the plan's garbage=3: garbage >= 2 compacts (renumbers) every object, so untouched widgets' /P, /Parent and /AP references change; garbage=1 still drops the appearance streams a refill orphaned.
- Task 6: write order is clears/"off" first, then values/"on", each in (page, top, left, input) order, so a missing-data field never wipes a value another field wrote to the same shared text field, and turning a checkbox kid off can't undo a sibling's "on" (Ruling J). Ruling G conflicts then go on the later target in page/top order and name both target keys (field id, or cell key for a cell).
- Task 6: a table column with wrap > 1 fits multi-line with max_lines = wrap and its created widgets get the multiline flag (empty slots too, for typing by hand); wrap 1 or unset is single-line. On an existing widget, wrap applies only when the widget is multi-line (its own flag, or an explicit Style.multiline per Ruling K). An existing widget's comb flag + MaxLen and MaxLen feed fit_text; Style.comb applies to created widgets only.
- Task 6: report shape: `fields` lists every non-table field (unmapped too, with paths=[]); `tables` lists every table (unmapped ones with path "" and zero rows) with one CellReport per slot, rows past the data included (empty). `paths[p].rendered` keys a column's cells `"<table>[<row>]"` for data rows only. `gaps` = unmapped fields, text boxes with nothing written, choice boxes whose data was missing or that weren't written, tables with no non-empty cell. `counts`: fields_written (text shown or box on), fields_empty, cells_written, plus one count per code in the top-level list (missing counted after collapse). Top-level warnings sort by (page, top, left) with page-less (record-level) warnings first. to_smart_pdf logs placement warnings on the `formcast.render.fill` logger.
- Ruling G2 (Task 6 fix, controller): choice slots are also grouped by bound widget name. Kids of one button field share one value, so two "on" writes to kids with different on-states clash; fill also reports an on + off pair on kids with the SAME on-state (the "off" kid shows on too). Pairs with the same on-state that are both on are harmless. The later target (page, then top) gets `shared_field_conflict`. After all writes, every written named/adopted button's report value is re-read from its /AS, so the losing field is reported off (or on), as it really shows.
- Task 6 fix (PyMuPDF 2.0): writing a checkbox kid puts /V on the kid as well as a string /V on the parent. PyMuPDF's `field_value` on a checkbox kid reads the inherited /V (the kid's own first), not /AS; a radio kid's reads /AS. So a sibling turned off by a later write still read as on. write_choice now sets the field's /V as a name (`_pdf_name`, #xx-escaped) and removes kid-level /V from the written kid and its siblings. Readers wanting one kid's visible state must use /AS; Task 9's read_written should use /AS for checkbox kids.
- Task 6 fix: slot-level warnings of a field with several source paths (path None) are listed under every one of its paths in `paths[p].warnings`. For list-row tables (schema item_type not object), every column maps to the item path `rows[]` (flatten_schema's). Their rendered keys are `"<table>[<row>][<key>]"`, and resolve's cell warnings are re-pathed to the slot's schema path. A table with no cell slots is a gap.
