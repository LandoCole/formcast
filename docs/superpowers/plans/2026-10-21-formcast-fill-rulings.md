- Task 1: Style rejects NaN/inf/<=0 for font_size and min_font_size, and an explicitly set min_font_size above a numeric font_size (Ruling D). An unset min is lowered to a smaller numeric font_size (Style(font_size=5) gives min 5); set_style with only font_size takes min(existing min, new size). - Task 2: resolve() record-level rules. unmapped_data flags leaf schema paths (scalar/enum/date/scalar-array, plus a list-of-objects path as one table) that have a non-missing value and aren't covered by a mapped field; a mapped table covers only its column keys (an uncovered column with data is flagged as `table[].col`), an unmapped table is flagged once at the table path. unknown_keys is one info warning listing schema-style paths of undeclared keys, skipped for objects where validation already reports "Additional properties". A bad table row's `invalid` goes in TableResolved.warnings (path = table path, row index in the message), its cells still exist with text None. Field warnings carry the field's page/rect; `missing` carries `path` only when the field has a single source path. Source.join is a separator applied only when the post-transform result is a list (no list_joined note then).
- Task 3: fit_text shrinks only on width (single line), on height+max_lines (multi-line), or on cell width+height (comb); a numeric font_size is never height-checked for single line. Multi-line overflow reports `lines` as the wrapped count at min_font_size. Comb cell width = rect width / n with no PAD; comb uses the widest glyph of the (cut) text. max_len and comb combine as min(). `\n` is a hard paragraph break when wrapping. pymupdf.get_text_length(text, fontname="helv", fontsize=...) works in PyMuPDF 2.0.
- Task 4: binding. (1) A signature-kind widget (named or adopted, field type signature) keeps its `how` and gets a `not_writable` warning; the writer skips it. (2) `choice_mark` targets never use or adopt foreign widgets and any `existing_widget` on one is ignored (no warning); see Ruling H. (3) Adoption excludes every widget whose name any non-choice_mark target names (not only the one picked), so unrelated cells never grab a sibling kid of a named radio/checkbox group; this includes widgets behind a `type_mismatch`. (4) Adoption order is page, rect top, rect left, key; ties between candidate widgets go to the lower page.widgets() index. (5) New names are assigned in input order of `targets`, suffixes `_2`, `_3`, … against all existing widget names (any page) and earlier new names. (6) `widget_name_for` turns the first `[n].` into `_r<n>_`; a plain field id containing that pattern would be read as a cell key. (7) Binding warnings carry field=target.field_id, page, rect=target.rect.

- Ruling H (Task 4 fix): a choice_mark may adopt (how="adopted", info `adopted`) an unclaimed existing checkbox widget named widget_name_for(key) or that name plus `_N`, with IoU >= 0.5 against its rect, so refilling a formcast-filled PDF doesn't stack a second circle mark; it adopts nothing else.
