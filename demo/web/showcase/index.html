How it works

formcast is a Python library. It turns a blank PDF form and a JSON Schema into a template, and a template, the blank form and a record into a filled PDF with a report. This page runs the same steps in your browser, without the agent: the detector, your links and the fill.

1 · Page map. The form first becomes a page map: its words and lines of text with their positions, the form fields it already has, the printed rules near each blank, and the boxes the CommonForms detector proposes. Each box comes with its nearest label. A page without a usable text layer is read with OCR.

2 · Agent. An AI model gets the page map as compact text and writes Python that runs against it. Query helpers find words, the text to the right of or below an item, and the candidate boxes on a page. Edit operations link a box to a schema path, add or split boxes, group choices and build tables. The agent starts from a seeded template, one box per form field and per detector box, and edits it step by step; each step reports what changed and what was refused.

3 · Template. The result is JSON: every box with its page, position and type, the schema path it reads, and any transforms, such as a date format or a tick when a value is true. A person reviews and corrects it, and it reruns on new records with no model call.

4 · Fill. Filling writes real PDF form fields, so the output is still a form. The fill report lists text that had to shrink or didn't fit, and record data with no box to go in.

What the AI agent adds

Here, you do the agent's job. The detector only proposes boxes. In this page you link each box to a schema field, add the boxes it missed, and fix or remove the wrong ones.

In the library, the agent does it with tools, without vision. It never sees the page image. It reads the page map as text and geometry and works through the edit operations. That is enough to:

  • link each box to a schema path, with transforms where the form needs them;
  • add the fields the detector missed, most often checkboxes, signature lines and date lines;
  • read an underline in front of an option as a checkbox to mark;
  • split one long line into parts using the small labels under it, such as street, city, state and ZIP;
  • mark “circle one” choices, group choices, and build tables from rows of cells;
  • leave printed text alone when it only looks like a blank.

It keeps the detector's boxes. Without the image, the agent placed boxes worse than the detector: in earlier runs most of its moves and resizes left a box further from its blank. With the current code it can't move or resize a detected box, and it is told to add a box only where none sits on or next to a blank. Its job is the mapping.

Limits

Mapping is where the agent loses points now. On fillable forms it links nearly every field. On flat and scanned forms it often draws its own box beside a detected one and links that instead, links a list to the text box but not to the checkbox that goes with it, or drops a transform from one run to the next.

Scans are weak. On some scanned pages the detector misses most of the boxes, and a scan has no printed rules to place the missing ones against. Neither model in this page is reliable on scans; the library sends scanned pages to FFDetr and reads them with OCR. Finding lines and boxes in the image itself would be new work.

Long forms. The agent stops early or gives up on long, noisy forms, and those sessions cost the most, because every step resends the first message.

Drawn boxes. A blank drawn as a rectangle reaches the page map only as two rules, so the agent can put the field on the label row above it.

The answer key. Some of its conventions can't be inferred from the form, such as one box or two for a from–to date, and whether office-use blanks count.

The held-out run is incomplete. It stopped at the provider's usage limit, so there is no measure yet of how the agent does on forms it wasn't tuned on. Results has the details.

Credits and code

CommonForms. The detector is FFDNet from CommonForms, by Joe Barrow (the paper). Its dataset is Apache-2.0. This page loads the model weights from the author's Hugging Face pages, FFDNet-S and FFDNet-L, and only when you run the detector.

Libraries. pdf.js (Apache-2.0) draws the page, ONNX Runtime Web (MIT) runs the model and pdf-lib (MIT) writes the filled PDF. They are copied into the page, not loaded from a CDN.

Sample forms. The W-9, W-4 and I-9 are US federal government forms, in the public domain. The sample records are made up.

Code. The formcast repository holds the library, the eval and this page.
